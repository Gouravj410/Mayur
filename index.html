Relational Database Design

8-Table Relational Schema Architecture

Engineered for 3rd Normal Form (3NF) with strict referential integrity, ON DELETE CASCADE foreign keys, and synchronized financial calculations.

users

Customers & Admin staff authentication records.

• id (PK)
• full_name, email (UQ)
• phone, address
• password_hash
• role ('admin'/'customer')
vehicles

Automobile registrations mapped to customers.

• id (PK)
• customer_id (FK → users)
• registration_number (UQ)
• brand, model, year
• fuel_type, vehicle_color
services

Standardized workshop maintenance packages.

• id (PK)
• service_name
• description
• base_charge
• estimated_duration
bookings

Customer appointment slots & tracking status.

• id (PK)
• customer_id, vehicle_id
• service_id
• booking_date, time_slot
• status ('pending', 'approved', etc.)
repairs

Technician diagnostic job cards.

• id (PK)
• booking_id (FK → bookings)
• technician_notes
• diagnostic_details
• labor_charge, repair_status
spare_parts

Workshop parts inventory with stock counters.

• id (PK)
• part_name, part_number (UQ)
• unit_price
• stock_quantity
• minimum_threshold
repair_parts

Junction table deducting inventory stock.

• id (PK)
• repair_id (FK → repairs)
• part_id (FK → spare_parts)
• quantity_used
• unit_price_at_repair
bills

Itemized synchronized tax invoices.

• id (PK), invoice_number
• booking_id, customer_id
• total_service_charge
• total_parts_charge, grand_total
• payment_status, payment_method
Examination Viva Preparation

Examiner Viva Defense & Question Bank

Curated answers to the top conceptual and implementation questions frequently asked by professors during computer science project viva examinations.

Answer: Flask is a micro-framework that provides granular control over routing, database connections, and session management without the overhead of Django's heavy ORM and administrative baggage. For a mini-project focused on demonstrating core relational database queries, modular Blueprints, and clean MVC separation, Flask offers clearer visibility into every SQL operation.

Answer: In database/db.py, the system attempts to establish a PyMySQL connection on port 3306. If the MySQL server is offline or not installed on the evaluation machine, the application catches the socket connection error and seamlessly falls back to a local SQLite database (car_service.db). This guarantees 100% demonstration availability during offline viva examinations.

Answer: When a technician assigns spare parts to a job card, the system executes an INSERT into the junction table repair_parts and simultaneously updates the stock_quantity in spare_parts using a database transaction: UPDATE spare_parts SET stock_quantity = stock_quantity - ? WHERE id = ?. This prevents race conditions and ensures live stock accuracy.

Answer: All SQL queries throughout the repository use parameterized placeholders (? for SQLite, %s for PyMySQL). Dynamic user inputs are NEVER concatenated directly into SQL strings, ensuring total immunity against SQL injection attacks.

Answer: User passwords are encrypted using Werkzeug's secure generate_password_hash (PBKDF2 with SHA-256 and cryptographic salt) before storage. During login, check_password_hash verifies passwords against the hash. Sessions are managed through Flask's signed, HTTP-only session cookies.
